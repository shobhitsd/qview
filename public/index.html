QView Quantum Readiness — Complete User Guide

Step-by-step: How to scan, read scores, and navigate every tab of the platform

🔐

Welcome to QView — Your Quantum Cryptography Intelligence Platform

QView scans your codebase, certificates, and dependency files to find every piece of cryptography that is vulnerable to future quantum computers — and tells you exactly how to fix it, with zero hallucinations.

⚡ Quick Start in 3 Steps

1
Point to Your Code

In the Scan Target bar at the top of the page, type the folder path containing your code. On a local server, this is a path on the machine running QView — for example sample_data (the built-in demo), C:/myproject, or a relative path like ../my-service.

💡 Not running locally? The deployed version loads a pre-scanned demo dataset automatically — no path needed. Just click Run Scan to re-run the demo.
2
Click "Run Scan"

Press the blue Run Scan button in the top-right. A progress bar appears. QView will scan every .py, .js, .ts, .go, .java, .pem, .cer, requirements.txt, package.json, pom.xml, build.gradle, and YAML file it finds and extract every cryptographic primitive, key size, and library reference.

3
Explore Your Results

After scanning, all 7 tabs are populated with live data. Start with Executive Overview to see your organisation's top-line risk scores, then dive into Crypto Universe to see individual findings.

🖊 How to Enter the Scan Path

A
Using the demo (default)

The field is pre-filled with sample_data. Click Scan to analyse QView's built-in polyglot test suite covering Java, Python, Go, TypeScript, certificates, and dependency files.

B
Scanning your own project (local deployment)

Replace the path with an absolute or relative folder path on the machine hosting QView. Examples:

  • C:/Users/you/projects/my-app — Windows absolute path
  • /home/user/services/payment-api — Linux / macOS absolute path
  • ../my-microservice — relative to QView's root directory
⚠️ On the Vercel-hosted demo, only the built-in sample_data folder is available. To scan your own code, run QView locally: git clone https://github.com/shobhitsd/qview && python server.py
C
Re-running a scan

You can run as many scans as you like. Each scan refreshes all 7 tabs with the new results. Use the Scan button next to the path field or the Run Scan button in the header.

📤 Exporting Results

  • Export CBOM (header button) — Downloads a cbom.json file in the CycloneDX 1.6 schema. Accepted by Dependency-Track, NIST SBOM tools, and supply-chain risk platforms.
  • CSV Export (inside Crypto Universe tab) — Downloads all discovered assets as a spreadsheet for Excel or Google Sheets.

Tab 1 — Executive Overview

Your CISO-level command centre for the organisation's overall risk posture at a glance.

  • Score Gauges — Three animated circular gauges show QRI, QEI, and CAI. Hover any gauge for a tooltip. QRI and CAI should be high; QEI should be low.
  • Radar Chart — 8-axis spider chart breaks QRI into sub-dimensions: Discovery Completeness, Algorithm Compliance, Key Strength, Agility, Certificate Health, Dependency Security, Protocol Hardness, and Mosca Safety.
  • Mosca Simulator — Drag the X, Y, Z sliders. A red VIOLATION badge appears if X+Y > Z. This shows whether your organisation is already HNDL-vulnerable.
  • Summary Cards — Asset counts, vulnerability counts, critical P1 findings, and compliance status at a glance.

Tab 2 — Crypto Universe

A full searchable inventory of every cryptographic asset found in your scan.

  • Search box — Type any algorithm name (e.g. RSA, AES, SHA-1), file name, or library to filter instantly.
  • Filter buttons — Switch between "All", "Vulnerable", "Safe", "Certificates" to narrow the view.
  • Asset cards — Show algorithm, key size, file path, line number, risk badge, and the library/API used. Click any card to jump to the Evidence Center.
  • Risk badge colours: 🔴 Critical P1 · 🟠 High · 🟡 Moderate · 🟢 Safe.
  • Export CSV — Downloads all assets as a spreadsheet.

Tab 3 — Quantum Heatmap

A 4×4 risk matrix plotting Business Criticality (vertical) against Quantum Exposure (horizontal).

  • Top-right quadrant (high criticality, high exposure) = most urgent P1 priorities.
  • Click any coloured cell to see which assets fall in that quadrant.
  • Dark red = Critical P1, Orange = High, Yellow = Moderate, Green = Safe.

Tab 4 — Compliance Radar

Shows how your cryptography stacks up against 5 major regulatory frameworks: NIST SP 800-131A, HIPAA, PCI-DSS 4.0, SEBI CSCRF, and CNSA 2.0. Red rows = active violations. Click any row to see the offending assets in the Evidence Center.

Tab 5 — Migration Cockpit

Step-by-step NIST FIPS PQC transition roadmap in 5 waves: Wave 0 (broken algorithms), Wave 1 (long-lived data), Wave 2 (hybrid PQC), Wave 3 (full PQC deployment), Wave 4 (crypto-agility automation). Each wave includes copy-paste code playbooks in your detected language.

Tab 6 — Knowledge Graph

Interactive network diagram of cryptographic dependencies. Drag nodes to reposition · Drag background to pan · Scroll wheel or +/- buttons to zoom · 0 to reset. Blue = files, Orange = algorithms, Green = libraries, Purple = assets.

Tab 7 — Evidence Center

IDE-style source code viewer with deterministic evidence. Open it by clicking any asset card (Crypto Universe) or any heatmap cell. The left sidebar lists all findings by severity. Clicking a finding shows the exact source line, risk analysis (Shor's feasibility, Grover speedup), and a copy-paste PQC remediation snippet.

📊 The 3 Core Quantitative Scores

QRI — Quantum Readiness Index

Range: 0–100 · Higher = better · Target: 90+

Formula: QRI = BaseScore × CoverageFactor. BaseScore = weighted average of 8 sub-dimensions. CoverageFactor scales down scores for incomplete scans.

QEI — Quantum Exposure Index

Range: 0–100 · Lower = safer · Target: <20

Penalised by RSA/ECC key sizes (Shor's breakability), short hash digests (Grover speedup), data classification weight (HIPAA/PCI), and business criticality.

CAI — Crypto Agility Index

Range: 0–100 · Higher = more agile · Target: 70+

Rewards algorithm provider abstraction, configurable key sizes, factory patterns. Penalises hardcoded algorithm strings and inline key generation.

⚖️ Mosca's Inequality

X + Y > Z ⟹ HNDL Vulnerable NOW
  • X — Data Shelf-Life: Years your sensitive data must stay confidential. Medical records = 25 yrs, PAN card = 15 yrs.
  • Y — Migration Time: Years to re-engineer, test, certify, and deploy PQC across your estate. Large enterprises: 5–8 yrs.
  • Z — Time to Quantum Threat: Consensus estimate for a CRQC breaking 2048-bit RSA. Default: 7 years (conservative).
💡 Example: EHR system with X=20 (medical shelf-life), Y=5 (migration), Z=7 (quantum timeline) → 20+5=25 > 7 → HNDL Vulnerable. Start migrating NOW.
